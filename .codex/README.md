# Codex для Local Design Studio

[AGENTS.md](../AGENTS.md) содержит краткие правила разработки;
[PROJECT.md](PROJECT.md) — альтернативное описание продукта, архитектуры и данных.
Инструкции по областям лежат в src/core, src/service, src/studio и, если он есть,
в desktop. При работе из корня их читает агент перед правкой соответствующей области.

В [.codex/config.toml](config.toml) задан проектный default глубины high. Модель
выбирает пользователь; sandbox, approval policy и личные подключения не меняются.
Проектный config применяется в доверенном checkout. Для загрузки нового контекста
открой студию отдельным проектом Codex и начни новую сессию.

Это контекст **разработки кода студии**. MCP студии — отдельный интерфейс работы
с **пользовательским дизайн-документом**. Добавление этих файлов само по себе не
подключает MCP-клиент и не открывает папку дизайна.

Примеры запросов:

```text
Добавь ... Критерии: ... Проверь browser-сценарий в light и dark.
Измени операцию ... Проверь atomic batch, revision conflict и повтор requestId.
Проверь MCP ... на временном проекте, без отключения ручного review.
Подготовь desktop-сборку ... и проверь именно упакованное приложение.
```

Разрешение на изменение исходников не означает разрешение переписать пользовательский
project.json или включить auto-apply. Для работы агента с дизайном сначала прочитай
capabilities/schema и действующую политику владельца. Публичные примеры и demo используют
дизайн-систему самой студии; приватный продукт остаётся отдельной доверенной библиотекой.

После правки описания проверь локальные Markdown-ссылки, TOML и git diff --check.
Продуктовые проверки выбирай по диффу и действующему CI. Инструкции обновляй вместе
с изменением границ кода или контракта; личные пути, connection tokens и env values
в эти файлы не входят.

Формат автоматической загрузки инструкций:
[официальная документация Codex](https://learn.chatgpt.com/docs/agent-configuration/agents-md).
