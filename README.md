# Local Design Studio

Open source студия интерфейсов с локальными файлами и общим документом для человека и AI-агента.

[Открыть интерактивное демо](https://aquahitt.github.io/local-design-studio/) · [MIT](LICENSE) · [Roadmap](ROADMAP.md) · [Участие](CONTRIBUTING.md)

Студия показывает настоящие React-компоненты, их состояния и темы; позволяет собирать компонентные экраны, редактировать JSON-свойства и токены. Изменения сохраняет локальный сервис. Агент читает тот же проект через MCP и предлагает проверяемые пакеты изменений. Это работающая основа компонентной дизайн-студии; свободный векторный холст и импорт из Figma ещё находятся в roadmap.

## Демо в браузере

[GitHub Pages](https://aquahitt.github.io/local-design-studio/) показывает ту же студию на синтетическом проекте: компоненты, темы, токены, экраны, отмену и подтверждение примерной агентской правки. Изменения сохраняются только в localStorage этого браузера; кнопка «Сбросить демо» возвращает исходные примеры. AI/MCP в демо имитируются. Для работы с файлами и настоящими агентами установи студию локально.

```bash
npm run build:demo
npm run preview:demo
npm run test:demo
```

Демо собирается для пути `/local-design-studio/`. Режим `demo` исключает внешний `STUDIO_LIBRARY_ROOT` и файловый сервис независимо от локального окружения. Workflow Pages проверяет сборку и поведение в браузере перед публикацией; изменения `main` обновляют сайт автоматически. В период разработки демо также публикуется из `codex/github-pages-demo`.

## Запуск

Требуется Node.js 24.2+ и npm. Версии зависимостей закреплены в lockfile.

```bash
npm ci
npm run studio
```

Открыть http://127.0.0.1:5178. По умолчанию создаётся игнорируемая Git папка `.studio-project` с публичной примерной библиотекой. Для своего проекта укажи отдельную папку:

```bash
STUDIO_PROJECT=/absolute/path/to/design-project npm run studio
```

Создание разрешено только в пустой папке. Существующий `project.json` открывается; повреждённые файлы и неподдерживаемые версии отклоняются. Загрузка зависимостей требует интернета; работа с установленной студией и локальными ресурсами не требует GitHub или облачного AI. Статическая сборка не запускает файловый сервис: для редактора нужен `npm run studio`.

## Работа в студии

1. В «Компонентах» найди компонент, выбери состояние и нажми «На экран +».
2. В «Экранах» выдели слой, измени «Свойства JSON» и нажми «Применить свойства». Ширина экрана сохраняется; масштаб относится к просмотру.
3. В «Основах» смотри и редактируй типизированные токены, меняй тему или экспортируй вычисленные JSON/CSS значения. Привязка свойства: `{"size":{"$token":"text-size"}}`; обычное значение свойства — локальное переопределение. Ссылки в проекте сохраняются при смене темы.
4. В «Предложениях агента» проверь автора, ревизию, изменения свойств и точный пакет операций. Подтверждение применяет пакет целиком; одна отмена отменяет весь пакет.
5. «Документ» показывает канонический JSON. «Экспорт проекта» выгружает этот JSON; для переноса проекта с ресурсами копируй всю папку, включая `assets/` и `fixtures/`.

Статус «Сохранено локально» появляется после подтверждённой записи на диск. Внешние изменения через сервис сохраняют выделение и незавершённый ввод. При конфликте сначала явно выбери перебазирование ввода. При удалении выбранного слоя черновик остаётся доступным для копирования или сброса. Undo/redo общие для ручных и агентских правок.

Старый Puck-пилот доступен по `/pilot` и остаётся отдельной демонстрацией с экспортом из памяти; его правки не меняют основной файловый проект.

## Подключение библиотеки

Чистая установка содержит `studio-example@1.0.0` и совместимые компоненты пилота `builtin@1`. Внешняя библиотека подключается оператором при запуске:

```bash
STUDIO_LIBRARY_ROOT="$(pwd)/examples/library/external" npm run studio
```

Папка содержит `studio.library.json` и React-модуль; [SDK, пример, миграции и модель доверия](examples/library/README.md). Проект с неизвестной библиотекой или компонентом сохраняет исходные данные и показывает диагностику. Документ не загружает библиотеку самостоятельно.

Есть адаптер локального monorepo с `packages/ui` и четырьмя вариантами тем PWA/web. Он использует исходные реализации и синтетические примеры, не копирует код продукта в репозиторий студии. Укажи абсолютный корень доверенного checkout через `STUDIO_LIBRARY_ROOT`; зависимости продукта должны быть установлены. Каталог отдельно отмечает компоненты, которым нужен контекст приложения.

Библиотеки — явно доверенный код. Превью работает в отдельном iframe с собственным runtime, чтобы CSS, порталы и модальные окна не ломали редактор. Это не песочница для недоверенного JavaScript. Сборка с внешней библиотекой содержит её исходный код и ресурсы; держи такую сборку локально.

## MCP и работа без редактора

Запуск stdio MCP требует явного пути проекта:

```bash
npm run mcp -- --project /absolute/path/to/design-project
```

Для подключения клиента запускай Node напрямую, чтобы служебный вывод npm не попал в stdio протокол:

```json
{
  "mcpServers": {
    "local-design-studio": {
      "command": "/absolute/path/to/node",
      "args": [
        "--import",
        "tsx",
        "src/service/mcp.ts",
        "--project",
        "/absolute/path/to/design-project"
      ],
      "cwd": "/absolute/path/to/local-design-studio",
      "env": { "STUDIO_LIBRARY_ROOT": "/absolute/path/to/trusted-library" }
    }
  }
}
```

Используй одинаковые пути проекта и библиотеки для UI и MCP. Если сервис уже работает, MCP подключается к нему. Иначе MCP запускает единственного headless-владельца; UI может подключиться позднее. Для отдельного сервиса: `npm run service -- --project /absolute/path/to/design-project --port 5190`.

Инструменты: `schema_read`, `capabilities_read`, `project_read`, `pages_list`, `document_read`, `components_list`, `tokens_read`, `editor_context`, `proposal_create`, `proposal_read`, `proposal_apply`, `undo`. Чтение узлов возвращает `pagination.nextOffset`; предел страницы 500 узлов. Контекст включает выделение, viewport и bounds, а после закрытия UI явно сообщает отсутствие соединения. Инструментов shell и произвольного доступа к файлам нет.

Порядок работы агента: прочитать capabilities/schema и проект → получить выделенный ID → создать предложение с текущей `baseRevision` и уникальным `requestId` → пользователь подтверждает в UI → проверить результат. MCP не может выдать себе ручное подтверждение. Устаревший пакет отклоняется целиком. Повтор запроса с тем же содержимым безопасен; другое содержимое с тем же ID отклоняется.

Ручное подтверждение включено по умолчанию. Оператор может явно задать `STUDIO_AUTO_APPLY=1` **при запуске владельца**: новые предложения тогда одобряются автоматически и могут применяться агентом. Подключение к уже запущенному владельцу не меняет его политику.

## Файлы и Git

`project.json`, `assets/`, `fixtures/` — переносимые данные. `.studio/` — приватные ключи подключения, блокировка, журнал, история и аудит. Добавь `.studio/` в `.gitignore` отдельного репозитория проекта. Репозиторий студии уже игнорирует эти файлы.

Git commit/push выполняется обычными инструментами или агентом по поручению пользователя; встроенная Git-панель и автоматическая синхронизация ещё в roadmap. GitHub необязателен. Клонирование переносимых данных создаёт новую локальную историю; копирование `.studio/` допускается только между остановленными владельцами и переносит приватные данные.

Формат, ограничения, восстановление и конфликт внешней правки: [docs/project-format.md](docs/project-format.md).

## Проверки

```bash
npm test
npm run typecheck
npm run build
npm run test:browser
STUDIO_LIBRARY_ROOT="$(pwd)/examples/library/external" npx playwright test tests/studio-external.spec.ts
```

При отсутствии браузера: `npx playwright install chromium`. Playwright поднимает независимый сервер на 5198 и временный проект; порт должен быть свободен. Скриншоты создаются в `test-results/`. Проверка реального адаптера: `STUDIO_LIBRARY_ROOT=/absolute/path/to/product npm test` и `npx playwright test tests/studio-local.spec.ts` с той же переменной.
