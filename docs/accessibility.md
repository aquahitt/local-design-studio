# Клавиатура, доступность и язык студии

Студия по умолчанию открывается на русском. Переключатель «Язык студии» / “Studio language” меняет текст интерфейса, подписи доступности и системные диалоги desktop. Выбор сохраняется отдельно от документа в localStorage. Имена проекта, слоёв, групп, определения компонентов, текст макета, комментарии и исходные свойства не переводятся. Превью получает только enum языка через проверенный postMessage; это не путь к исполняемому коду.

## Команды

`src/studio/shortcuts.ts` содержит общий обработчик registry команд. `Mod` — Command в macOS, Control в Windows/Linux. Сочетания работают с физическими клавишами и русской раскладкой. Обработчик не перехватывает ввод в input/textarea/select/contenteditable, IME composition, повтор удерживаемой клавиши и уже обработанные события. Неактивная команда не подавляет системное поведение.

| Действие                   | macOS              | Windows / Linux    |
| -------------------------- | ------------------ | ------------------ |
| Отмена                     | Command+Z          | Control+Z          |
| Повтор                     | Command+Shift+Z    | Control+Shift+Z    |
| Дублировать выбранные слои | Command+D          | Control+D          |
| Копировать выбранные слои  | Command+C          | Control+C          |
| Вставить слои              | Command+V          | Control+V          |
| Удалить выбранные слои     | Delete / Backspace | Delete / Backspace |

Клавиатура и кнопки используют одинаковые операции, revision guard и шаги отмены. Несохранённый ввод блокирует команды документа. Черновик определения компонента блокирует уход и остальные изменения, но собственное сохранение остаётся доступным. HTML `aria-keyshortcuts` сообщает сочетания кнопок команд слоёв.

В пользовательском select: Enter или стрелка открывает список, поиск получает фокус; стрелки/Home/End выбирают активную строку, Enter подтверждает, Escape закрывает и возвращает фокус на кнопку. Диалог групп использует нативный `<dialog>`; Escape закрывает его и фокус возвращается на открывшую кнопку.

## Проверка

```bash
npm run test:accessibility
npm test -- src/studio/shortcuts.test.ts src/studio/i18n.test.tsx src/studio/i18n-resources.test.ts
```

Автоматический профиль `tests/accessibility` использует отдельный файловый проект и loopback-порты 5229/5230. Реальные пользовательские данные в проверке не участвуют. Playwright + axe проверяют WCAG A/AA, включая 2.1 AA, в русском и английском интерфейсах встроенной библиотеки студии.

`keyboard-flow.spec.ts` проходит оба языка через настоящий порядок Tab: открытие и закрытие select, диалог групп и возврат фокуса, создание и переименование группы, создание экрана и текста, редактирование JSON свойств, подтверждение предложения агента, JSON snapshot и React ZIP. Кнопки активируются Enter; локаторы `.focus()`, `.click()` и DOM-имитация клавиатурных событий в этом пути не используются. Предложение создаёт агент через настоящий HTTP API; одобрение и применение делает пользовательский UI с клавиатуры. Backspace в редакторе свойств не удаляет слой. JSON snapshot точно совпадает с документом на диске; React ZIP содержит ожидаемые файлы и применённый текст.

Сценарий останавливает fixture-процесс Vite и владельца файлов, запускает новый процесс с той же папкой, заново выбирает экран и слой клавиатурой и проверяет документ на диске, текст слоя и сохранённый язык. Перезагрузка страницы сама по себе не считается перезапуском приложения. Это проверка development-студии; launcher и установленная Electron-оболочка относятся к отдельному desktop-профилю.

Axe проверяет каталог, диалог групп, выбранный слой/инспектор, ожидающее предложение и повторно открытый проект в светлой теме. Отдельные RU/EN тесты проверяют каталог, диалог и inspect/React handoff в тёмной теме. Тема и язык для контрастных тестов задаются в localStorage до загрузки как fixture setup. Клавиатурный выбор нативной темы в этот аудит не входит: macOS headless Chromium не управляет системным popup нативного `<select>`, что воспроизведено также на минимальном HTML вне приложения. Английский язык в основном пути выбирается настоящим клавиатурным type-ahead по опции “English”, после чего проверяется `html[lang=en]`. Для нативного `<dialog>` допустим переход Tab в chrome браузера; пока документ имеет фокус, элементы за модальным диалогом фокус не получают.

`studio.spec.ts` дополнительно проверяет custom select, сохранение языка после reload, неизменность пользовательского имени/текста, команды слоя с undo и защиту обычного ввода. Отдельный регрессионный сценарий переключает язык при несохранённом вводе: выбранный экран/слой и draft сохраняются, файловое соединение остаётся тем же, статус сохранения использует актуальный язык. В `StudioApp` долгоживущие callbacks читают актуальный переводчик через ref, сохраняя стабильные зависимости подключения.

Низкий контраст muted/subtle текста светлой темы ранее исправлен после фактического отчёта axe. Автоматизация не доказывает доступность произвольного стороннего компонента, подключённого оператором, и не заменяет ручное чтение экрана.

### Ручной gate для #29

**VoiceOver/NVDA не запускались; ручная приёмка отложена. Issue #29 остаётся открытой до фактического прогона.** Зелёные axe/Playwright проверки не подтверждают речевые объявления или работу установленной оболочки со screen reader.

Ручная матрица: установленное приложение macOS + VoiceOver и Windows + NVDA, русский и английский UI, светлая и тёмная темы. Для каждой комбинации пройти клавиатурой: launcher → создать/открыть проект → sidebar → библиотека/select → создать экран/слой → редактировать инспектор → создать/изменить группу → проверить и подтвердить предложение → экспорт → закрыть приложение → запустить и открыть тот же проект.

Во время прогона проверить объявления названий, выбранных/заблокированных состояний, текущего значения select, ошибок и статуса сохранения. Проверить доступность каждого действия, порядок Tab/Shift+Tab, Escape, отсутствие доступа к фону при открытом dialog, возврат фокуса, защиту ввода от команд слоя и сохранность пользовательского текста после смены языка.

В протокол записать дату, ОС/архитектуру, версию установленного приложения, screen reader и его версию, UI-язык, тему и клавиатурную раскладку. Для каждого шага сохранить ожидаемое/фактическое объявление и результат; дефект — с воспроизводимыми шагами. Закрывать ручной gate можно после успешного повторения исправленных сценариев и прикрепления фактического протокола к #29. До этого результат ограничен автоматической частью приёмки #29/#72.
