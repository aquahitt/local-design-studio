# ADR 0001: переносимая сцена и граница Puck

Дата: 2026-10-05. Статус: принято для первого прототипа alpha.3.

## Решение

`project.json` остаётся источником истины. `schemaVersion: 2` расширяется
необязательными полями; существующие документы не получают пустые поля при чтении.
[JSON Schema](scene-v2.schema.json) и [проверяемый пример](scene-v2-example.json)
фиксируют контракт. Пример содержит вложенный фрейм, текст, вектор и экземпляр
локального дизайн-компонента. Исполняемый код, URL библиотек и пути вне проекта
не входят в документ.

Узел сохраняет прежние `id`, `type`, `props`, `slots`. Необязательные `name`,
`hidden`, `locked` задают состояние слоя. Необязательный `scene` задаёт вид
`frame | text | vector | component | image`, локальные `x`, `y`, `width`, `height`
и декларативный стиль: `rotation`, `opacity`, `fill`, `stroke`, `strokeWidth`,
`radius`, `clip`, `path`, `fontSize`. Геометрия — CSS px, угол — градусы по часовой
стрелке относительно верхнего левого угла. Масштаб камеры не меняет документ.
Размеры положительны; координаты ограничены миллионом px, прозрачность — 0…1.
Цвет не может содержать CSS `url()`, путь вектора содержит только команды SVG path.
Изображение хранит относительный `props.src` в `assets/`; параметры crop — обычные
данные props, поддерживаемые renderer, без загрузок из сети.

Массивы `pages[].nodes` и массивы слотов задают порядок от заднего слоя к переднему.
Дочерние слои наследуют преобразование, hidden/locked и clipping предков.
Группы `project.groups` продолжают группировать страницы, компоненты и токены;
они не становятся группами слоёв. Группа слоёв — фрейм со слотом `content`.
ID всех сохранённых узлов уникальны в документе, включая узлы определений.
`screenId`, `projectId`, ID определения и token names сохраняются после clone.

## Выбор renderer

Рассмотрены три подхода:

1. DOM/CSS со вложенными преобразованиями и SVG для векторов: прямое отображение
   текста, доступность, существующие React-компоненты и инспектор сохраняются.
2. Canvas 2D: меньше DOM-элементов, но потребовались бы отдельная модель текста,
   accessibility и слой React overlays.
3. WebGL: подходит для больших сцен, требует существенно большей инфраструктуры.

Первый прототип использует DOM/CSS + SVG. Математика камеры и hit testing вынесена
в чистое ядро `src/core/scene.ts`; renderer и UI используют тот же контракт.
Puck остаётся адаптером зарегистрированных React-компонентных экранов. Он не
определяет переносимый формат свободной сцены и не исполняет содержимое документа.
Примитивы `SceneFrame`, `SceneText`, `SceneVector`, `StudioImage` не обязаны
регистрироваться как пользовательские React-компоненты.

## Дизайн-компоненты

`designComponents` — необязательный массив `{id,name,version,nodes,variants?,properties?}`.
Это авторские определения сцены, отдельно от доверенного React registry.
`instance: {definitionId,variant?,overrides?}` ссылается на стабильное определение.
Вариант — набор patches props по ID узлов определения. `properties` связывает имя
публичного свойства с `{nodeId,prop,default}`. Overrides тоже адресуют ID исходных
узлов и могут менять существующие свойства совместимого типа, включая scalar
значение вместо token reference того же типа.

Разрешение экземпляра применяет исходник → defaults properties → вариант → явно
заданные properties экземпляра → overrides. Вложенные экземпляры разрешаются тем
же способом. Renderer получает временные IDs вида `instance::source-node`; эти
IDs не отправляются в операции. UI выбирает содержащий сохранённый экземпляр.
Циклы, отсутствующие определения, варианты и устаревшие override targets дают
диагностику; несовместимое обновление отклоняется целиком, без потери overrides.
`version` — версия определения для оператора; отсутствие target/type определяется
по фактическому контракту, а не по одному числу версии.

`detachInstance` оставляет ID, геометрию и положение wrapper и создаёт независимые
потомки с новыми IDs. Их текст, варианты, свойства и вложенные экземпляры уже
материализованы. Правка исходного определения после detach на них не влияет.

## Команды и clipboard

Изменения выполняются через `applyBatch` и прежний durable ProjectStore;
undo/redo, receipt и конфликты ревизий общие с компонентными экранами.
`setNodeMetadata`, `setDesignComponents`, `setInstance`, `detachInstance` добавлены
в опубликованную batch schema. Остальные команды используют `insertNode`,
`moveNode`, `removeNode`, `updateProps`, `setTokens`.

Скрытый слой хранится в дереве, но не участвует в hit testing. Locked слой и его
потомки не принимают правки, move, delete или insertion. Снять lock самого узла
можно отдельной операцией; lock предка этим не обходится. Удаление/перенос фрейма
с locked потомком тоже отклоняется. Изменение `kind`, координат, размеров или
поворота такого предка через `setNodeMetadata` также отклоняется: потомок не должен
сдвигаться/масштабироваться в обход блокировки. Имя, заливка и неизменная геометрия
предка остаются редактируемыми. Изменение определения компонента может
обновить locked экземпляр: lock защищает прямые правки слоя, а не наследование.

`copyLayers` удаляет повторное копирование выбранных потомков выбранного предка.
Clipboard содержит выбранные узлы, зависимые определения, токены и список assets.
Paste создаёт новые IDs, переписывает definition links, override targets и property
bindings. Конфликты token names, включая цепочки aliases, разрешаются новым именем,
без изменения существующих destination tokens. Сами bytes assets не включаются
в clipboard: вставка в другой проект возвращает `MISSING_ASSET`, оставляя ссылку
для явного импорта оператором. Дубликат внутри проекта переиспользует определения.
Ссылка на новый узел внутри произвольных props не трактуется автоматически: явный
контракт ссылок сейчас есть у instances/properties/overrides и token refs.

Keyboard shortcuts и одинаковое выделение дерева/холста — ответственность UI.
Обработчик должен пропускать input, textarea, select и contenteditable. Чистые
helpers и batch engine не заменяют браузерную приёмку этих сценариев.

## Выравнивание и равные промежутки

`src/core/geometry-commands.ts` формирует обычные операции `setNodeMetadata`;
нового формата документа и отдельного пути сохранения нет. `translateSceneLayers`
принимает смещение в мировых CSS px и переводит его обратным преобразованием
родителя в локальные x/y. `alignSceneLayers` выравнивает минимум два независимых
выбранных корня по левому/центральному/правому или верхнему/центральному/нижнему
краю объединения их мировых axis-aligned bounds. Поворот, размеры и стиль
сохраняются; clipping и hidden не меняют расчёт явно выбранной геометрии.

`distributeSceneLayers` требует минимум три независимых корня одной страницы,
сохраняет крайние объекты и устанавливает равные неотрицательные промежутки.
Недостаток места возвращает `NEGATIVE_DISTRIBUTION_GAP` без изменения документа;
команда не переставляет объекты скрытым образом. Погрешность около нулевого
промежутка допускается только в пределах вычисленной floating-point точности.
Порядок при равных координатах определяется порядком документа. Выбранный потомок
выбранного предка не двигается дважды; все ID проверяются до удаления таких
повторов, поэтому locked потомок не обходит проверку.

`GeometryActions` предоставляет шесть команд выравнивания и две команды
промежутков в панели слоёв. Пакет привязан к revision документа, на котором
выполнен расчёт. Один пакет отменяется одним undo; уже достигнутое положение не
создаёт пустой шаг истории. Это не завершает инструменты жестов, resize/rotate,
snapping и направляющие из #9.

## Проверка координат и измерения

Регрессии проверяют экран ↔ мир при zoom 0.25, 1, 2, 4, pan, вложенный фрейм,
поворот 90°, clipping, перекрывающиеся слои и inherited hidden/locked. Hit testing
идёт от последнего нарисованного слоя к первому, сравнивая точку с обратным
преобразованием ограничивающего прямоугольника. Для векторов и текста это
bounding box; геометрия glyph/path не вычисляется.

Локальное измерение 2026-10-05, Node v24.2.0, 100 последовательных запросов:

| Узлы   | Время 100 queries | Среднее query |
| ------ | ----------------: | ------------: |
| 1 000  |          25.06 ms |       0.25 ms |
| 10 000 |         133.39 ms |       1.33 ms |

Измерение включает flatten/transforms/hit test, исключает DOM/layout/browser paint.
Это данные прототипа на одной машине, без обещания частоты кадров. Алгоритм O(n)
на запрос; spatial index и кэш transform можно добавить после browser profiling.
Лимиты документа прежние: 5 MB UTF-8, 100 страниц, 10 000 сохранённых узлов,
64 уровня; определения входят в общий бюджет. Материализованная сцена также
ограничена 10 000 узлами и 64 уровнями, чтобы nested instances не раздували рендер.
Камера не допускает нулевой/отрицательный/нечисловой zoom.

## Совместимость и переход

Миграция schema 1 проходит прежним `migrateProject`: одна страница получает прежний
`screenId`, узлы и их IDs/props/slots сохраняются, revision сохраняется.
Schema 2 с отсутствующим `scene` остаётся компонентным экраном. Groups, viewport,
включая device metadata, и token refs продолжают работать. Неизвестный `type`
сохраняется без попытки исполнения. Чтение не переносит координаты в props.

Старые читатели schema 2 с запретом unknown fields не понимают новые scene fields;
для них нужен экспорт без scene либо обновление приложения. Формат использует
совместимое расширение для нового reader, а не обещает поддержку старым бинарником.
Никакой автоматической записи или миграции чужого файла при чтении не происходит.
