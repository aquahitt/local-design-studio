# Варианты экранов и обсуждения

Вариант целого экрана — отдельная страница того же `project.json`. Операция `duplicatePage` копирует viewport, свойства, слоты, геометрию и ссылки на компоненты, назначает новые ID всем узлам страницы и сохраняет `provenance: {sourcePageId, sourceRevision}`. Исходная страница не меняется. Страница добавляется в те же группы, что и источник. Локальные assets, токены и определения компонентов остаются общими для проекта. Это отличается от `designComponents[].variants`: они меняют свойства экземпляров компонента, а не создают альтернативный экран.

```json
{
  "type": "duplicatePage",
  "pageId": "home",
  "newPageId": "home-option-b",
  "name": "Вариант B"
}
```

Обсуждения находятся в переносимом массиве `project.annotations`, а не только в `.studio`. Операция `setAnnotations` заменяет массив в одной транзакции. Для добавления или изменения комментария клиент читает текущий массив и создаёт предложение с актуальной `baseRevision`; общий движок отклоняет конфликт ревизии.

```json
{
  "id": "comment-1",
  "pageId": "home",
  "nodeId": "hero",
  "text": "Проверить длинный заголовок на мобильном экране",
  "status": "resolved",
  "decision": "Использовать вариант B",
  "proposalId": "proposal-id",
  "createdAt": "2026-10-06T00:00:00.000Z"
}
```

Обязательные поля — `id`, `text`, `status` (`open` или `resolved`) и `createdAt`. Можно привязать обсуждение к `nodeId`, странице, координатам `pageId` + `x` + `y` либо оставить его общим. `decision` и `proposalId` сохраняют решение и ссылку на предложение. Текст и решение ограничены 10 000 символами; массив — 10 000 обсуждениями; весь документ сохраняет общий лимит размера.

Удаление узла или страницы сохраняет комментарий. `readAnnotations(project)` и MCP `annotations_read` вычисляют `orphaned: true`, когда соответствующий якорь исчез или узел больше не принадлежит указанной странице. Это диагностическое поле не записывается в исходный документ. Ссылка на уже удалённую исходную страницу в provenance также остаётся историей происхождения.

`annotations_read` поддерживает фильтры `pageId`, `nodeId`, `status`, `orphaned` и `offset`/`limit` (максимум 500), возвращая revision и `pagination.nextOffset`. Агент меняет обсуждения через `proposal_create` с `setAnnotations`, создаёт варианты через `duplicatePage` и использует обычное подтверждение предложения в UI. Инструмент чтения не выдаёт одобрение.

Комментарии, решения и происхождение вариантов переживают перезапуск и копирование только `project.json`: состояние обсуждений не зависит от истории `.studio`. Ссылка `proposalId` при таком копировании остаётся текстовой ссылкой; история предложений переносится отдельно вместе с `.studio`.

Проверки: `npm test -- src/core/annotations.test.ts src/service/mcp.test.ts`. Core-тест перезапускает настоящий `ProjectStore`, затем открывает отдельный проект из копии только `project.json`. MCP-тест повторяет этот сценарий через реальный stdio SDK, проверяя решения, orphaned anchors и provenance.
