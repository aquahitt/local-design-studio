# Совместимость и восстановление проектов

Приложение читает schemaVersion 1 и 2, записывает только 2. Версия приложения и версия формата — разные величины. Неизвестная версия или поле отклоняются с ошибкой; документ не обрезается и не сохраняется частично. Чистый schema-2 проект без новых метаданных сохраняет IDs, группы, viewport, token bindings и неизвестные типы компонентов. Для их отображения нужна подходящая доверенная React-библиотека.

| Документ                                            | Новая студия                             | Старый alpha.2 binary                                               |
| --------------------------------------------------- | ---------------------------------------- | ------------------------------------------------------------------- |
| schema 1                                            | Валидация, резервная копия, миграция в 2 | Только если поддерживал исходную библиотеку                         |
| schema 2 без scene/instances/annotations/provenance | Чтение и запись                          | Базовый поддерживаемый формат                                       |
| schema 2 с новыми необязательными полями            | Чтение и запись                          | Может отклонить неизвестные поля; обратная совместимость не обещана |
| schema 3 или неизвестные поля                       | Отказ без изменения project.json         | Не поддерживается                                                   |

До установки новой alpha закройте приложение и сделайте полную копию папки проекта. Переносимая копия включает `project.json`, `assets/`, `fixtures/` и необходимые файлы вашей доверенной библиотеки. `.studio/` содержит журнал, предложения и локальные credentials: не публикуйте его. Копия только project.json не переносит бинарные assets или исходники библиотеки.

При первом открытии schema-1 файла владелец проекта сначала проверяет документ, затем синхронно записывает точные исходные байты в `.studio/backups/project-v1-<sha256>.json`, и лишь после этого материализует schema 2. Повторное открытие не создаёт новую копию тех же байтов. Ошибка записи, подмена копии или symlink останавливают миграцию; project.json сохраняется. Эта автоматическая копия защищает переход 1→2, но не заменяет полную резервную копию перед обновлением schema-2 проекта. На Windows содержимое файла flush выполняется, directory fsync недоступен.

Для отката закройте все процессы владельца проекта. Создайте новую папку, скопируйте туда исходный project.json из резервной копии и соответствующие assets/fixtures, откройте её нужной старой версией. Не подменяйте project.json внутри действующей `.studio/`: журнал нового проекта способен восстановить более позднюю ревизию. Изменения, сделанные после копии, автоматически назад не конвертируются.

Текущие пределы parser: 10 000 узлов, 5 000 000 байт сериализованного документа и глубина 64. 50 000 узлов не поддерживаются; отказ измерен в [performance.md](performance.md). Перед агентным редактированием можно прочитать `schema_read` и `capabilities_read`; write batch требует текущую ревизию, стабильный requestId и одобрение предложения. Оператор может явно включить auto-apply для доверенного headless окружения.

Снимок schema и пример находятся в [ADR сцены](adr/0001-portable-scene.md). Будущее несовместимое изменение требует новой версии формата, валидируемого преобразования и копии до первого rewrite. Не повышайте лимиты и не удаляйте поля ради открытия неподдерживаемого файла.
