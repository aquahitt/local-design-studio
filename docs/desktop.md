# Desktop alpha

[Скачать релиз](https://github.com/aquahitt/local-design-studio/releases). Electron включает Chromium и Node.js: пользователь запускает приложение, выбирает папку и работает. Терминал и ручной сервер не нужны. Приложение не загружает Pages demo для работы.

## Данные и работа

Создать проект: название → выбрать пустую папку. Открыть проект: выбрать папку с project.json. «Попробовать пример» создаёт сохраняемый проект в данных приложения. Недавние проекты хранят только название и путь. Через «Все проекты» завершается файловый сервис и освобождается блокировка.

Переносимые файлы: project.json, assets/, fixtures/. .studio/ содержит историю и приватные подключения; не публикуй её в Git. Настройки приложения хранятся в стандартной userData папке Electron. Пользовательские проекты не входят в пакет приложения. При работе с копией репозитория Git остаётся обычным Git, автоматического push нет.

Редактор имеет ограниченный preload API. Превью загружается на отдельном studio://preview origin, не получает Node/desktop bridge и не имеет API доступа к документу. Общий файловый владелец принимает только авторизованные loopback запросы. При закрытии процесс ждёт завершения операций. Существующий сервис может быть подключён только с совместимой библиотекой и origin; несовместимое подключение диагностируется.

## Границы alpha

Встроены example/builtin библиотеки. Внешние исходники React не собираются динамически внутри приложения; импорт готовых библиотек и MCP helper — следующий этап. Существующий MCP из исходников может подключиться к desktop владельцу с теми же метаданными, но требует окружения разработчика. После закрытия приложения встроенный владелец завершается. Выделение и viewport передаются агенту, но bounds узлов в desktop пока пусты: изолированное превью требует отдельного обмена геометрией.

Релизы unsigned: macOS Gatekeeper и Windows SmartScreen могут препятствовать запуску. Подпись и notarization не заявлены. Linux DEB ориентирован на Ubuntu/Debian; ZIP требует системные библиотеки Electron. Не обещаем portable поддержку любого дистрибутива Linux.

## Разработка и выпуск

```bash
npm ci
npm run desktop
npm run test:desktop
npm run make:desktop
npm run test:desktop:packaged
# Только macOS, после make:
node scripts/desktop/dmg.mjs
node scripts/desktop/checksums.mjs
```

Сборка включает только desktop-dist/, package.json и лицензии. Режим desktop игнорирует STUDIO_LIBRARY_ROOT и STUDIO_PROJECT. STUDIO_USER_DATA позволяет явно выбрать папку настроек (используется тестами). Ни один путь проекта не задаётся из загруженного документа.

Workflow Desktop builds проверяет исходную логику и упакованное приложение на macOS arm64/x64, Windows x64 и Linux x64. Артефакты PR временные. Push matching alpha тега desktop-v<package.version> публикует GitHub prerelease только после успеха всей матрицы. Повтор запуска обновляет assets того же alpha тега.

Сборка локально может использовать APPLE_SIGN_IDENTITY и установленный в Keychain сертификат; APPLE_ID/APPLE_APP_PASSWORD/APPLE_TEAM_ID задают notarization. Windows maker принимает WINDOWS_CERTIFICATE_FILE и WINDOWS_CERTIFICATE_PASSWORD. Эти настройки не включены в unsigned CI: публикация подписанного релиза требует отдельной конфигурации секретов и проверки подписи.
