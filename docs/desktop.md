# Desktop alpha

[Скачать релиз](https://github.com/aquahitt/local-design-studio/releases). Electron включает Chromium и Node.js: пользователь запускает приложение, выбирает папку и работает. Терминал и ручной сервер не нужны. Приложение не загружает Pages demo для работы.

## Данные и работа

Создать проект: название → выбрать пустую папку. Открыть проект: выбрать папку с project.json. «Попробовать пример» создаёт сохраняемый проект в данных приложения. Недавние проекты хранят только название и путь. Через «Все проекты» завершается файловый сервис и освобождается блокировка.

Переносимые файлы: project.json, assets/, fixtures/. .studio/ содержит историю и приватные подключения; не публикуй её в Git. Настройки приложения хранятся в стандартной userData папке Electron. Пользовательские проекты не входят в пакет приложения. При работе с копией репозитория Git остаётся обычным Git, автоматического push нет.

Редактор имеет ограниченный preload API. Превью загружается на отдельном studio://preview origin, не получает Node/desktop bridge и не имеет API доступа к документу. Общий файловый владелец принимает только авторизованные loopback запросы. При закрытии процесс ждёт завершения операций. Существующий сервис может быть подключён только с совместимой библиотекой и origin; несовместимое подключение диагностируется.

## Границы alpha

Встроены example/builtin библиотеки. В проекте нажми «Подключить библиотеку», выбери папку с `studio.library.json` (SDK manifest и TS/TSX entry) или корень поддерживаемого проекта с `packages/ui`. Приложение отдельно спросит, доверяешь ли ты исходникам: после подтверждения они собираются включённым компилятором и выполняются только на origin превью. Папка библиотеки выбирается через системный диалог, пути из `project.json` никогда не запускаются. Разрешение и путь сохраняются для проекта в `libraries.json` в userData, отдельно от переносимого документа. При повторном открытии библиотека собирается из текущих исходников. «Отключить библиотеку» удаляет это разрешение.

Приложение включает esbuild с нативным бинарником, JS-компилятор Tailwind и публичный адаптер: устанавливать Node/npm для работы не нужно. Внешние исходники и данные проекта не входят в пакет приложения. Если внешняя библиотека импортирует сторонние пакеты, её установленный `node_modules` должен находиться рядом с исходниками; приложение не скачивает зависимости. Импорты изображений и шрифтов встраиваются в bundle, шрифты поддерживаемого адаптера — в CSS. React и JSX runtime берутся из самого изолированного превью, чтобы hooks и контексты использовали один экземпляр React. Декларативные метаданные доступны редактору и сервису; код библиотеки в них не выполняется.

Превью получает только файлы текущего bundle. На origin редактора они недоступны; смена проекта отменяет доступ к предыдущему bundle. Ошибка сборки показывает диагностику и не меняет документ проекта. Существующий MCP из исходников может подключиться к desktop владельцу с теми же метаданными, но требует окружения разработчика. После закрытия приложения встроенный владелец завершается. Выделение и viewport передаются агенту; bounds в `editor_context` пока пусты, поскольку изолированное превью требует отдельного обмена геометрией. `document_render` и `inspect_read` получают реальные DOM bounds отдельного Chromium-снимка; PNG нормализуется к CSS pixels, включая Retina. Контракт описан в [render.md](render.md).

Alpha 2 имеет проверяемую ad-hoc подпись на macOS, но не Developer ID/notarization. Релизы не подписаны доверенным сертификатом: macOS Gatekeeper и Windows SmartScreen могут препятствовать запуску. Подпись и notarization не заявлены. Linux DEB ориентирован на Ubuntu/Debian; ZIP требует системные библиотеки Electron. Не обещаем portable поддержку любого дистрибутива Linux.

## MCP из установленного приложения

В настройках MCP-клиента укажи исполняемый файл приложения как `command`, а `args`: `["--studio-mcp", "--project", "/полный/путь/к/проекту"]`. Этот режим не открывает окно и не блокируется уже открытой студией. Он запускает включённый MCP bundle через встроенный Node Electron, используя stdio; отдельный Node/npm не нужен.

macOS:

```bash
"/Applications/LocalDesignStudio.app/Contents/MacOS/LocalDesignStudio" --studio-mcp --project "/Users/me/design-project"
```

Windows (PowerShell; путь зависит от установленной версии):

```powershell
& "$env:LOCALAPPDATA\LocalDesignStudio\LocalDesignStudio.exe" --studio-mcp --project "C:\Users\me\design-project"
```

Linux:

```bash
/path/to/LocalDesignStudio --studio-mcp --project /home/me/design-project
```

Если проект уже открыт в desktop, helper подключается к его файловому владельцу и метаданным. Если владелец не запущен, helper открывает локального headless владельца с встроенными библиотеками. Предложения агента сохраняются и ждут одобрения пользователя; это не включает автоматическое применение. Для screenshot/render возможностей desktop владелец должен быть открыт. После закрытия stdio helper освобождает принадлежащий ему проект.

## Разработка и выпуск

```bash
npm ci
npm run desktop
npm run test:desktop
npm run make:desktop
npm run test:desktop:packaged
# Только macOS, после make:
node scripts/desktop/dmg.mjs
node scripts/desktop/checksums.mjs
```

Сборка включает только desktop-dist/ (в том числе публичный компилятор, runtime-файлы, unpacked бинарник esbuild и исходники публичного SDK), package.json и лицензии. Нативный esbuild читает SDK из физической `app.asar.unpacked`, поскольку его файловый доступ не поддерживает виртуальную ASAR. Режим desktop игнорирует STUDIO_LIBRARY_ROOT и STUDIO_PROJECT. STUDIO_USER_DATA позволяет явно выбрать папку настроек (используется тестами). Ни один путь проекта не задаётся из загруженного документа.

Workflow Desktop builds проверяет исходную логику и упакованное приложение на macOS arm64/x64, Windows x64 и Linux x64. Артефакты PR временные. Push matching alpha тега desktop-v<package.version> публикует GitHub prerelease только после успеха всей матрицы. Повтор запуска обновляет assets того же alpha тега.

Сборка локально может использовать APPLE_SIGN_IDENTITY и установленный в Keychain сертификат; APPLE_ID/APPLE_APP_PASSWORD/APPLE_TEAM_ID задают notarization. Windows maker принимает WINDOWS_CERTIFICATE_FILE и WINDOWS_CERTIFICATE_PASSWORD. Эти настройки не включены в unsigned CI: публикация подписанного релиза требует отдельной конфигурации секретов и проверки подписи.

## Автоматическая desktop-приёмка

`tests/desktop.spec.ts` запускается и через `npm run test:desktop`, и на готовом executable через `npm run test:desktop:packaged`. Первый сценарий создаёт проект, меняет свойства/устройство/группы, проверяет файл на диске, повторное открытие, render и изоляцию preview. Второй открывает публичный synthetic проект и библиотеку из `tests/desktop-fixtures.ts`: проверяет отмену и подтверждение доверия, компиляцию библиотеки, компактные metadata, review предложения через UI, изменение Tabs props, точные размеры PNG страницы и обрезанного узла, React handoff и сохранность локальных разрешений.

Второй сценарий запускает приложение и MCP helper с пустым `PATH`, без `NODE_PATH`/`NODE_OPTIONS`, из посторонней рабочей папки. Один stdio-клиент продолжает работу после смены владельца при подключении библиотеки и после закрытия/повторного открытия desktop; второй helper подключается без замены credentials. В Chromium запрещены внешние HTTP/HTTPS/WS/WSS-запросы и проверено отсутствие таких попыток; локальный loopback остаётся доступен. Эта проверка использует автоматизированный MCP-клиент и synthetic данные, без приватного продукта.

Локальное прохождение 2026-10-09: macOS arm64, Node.js 24.2.0, Electron 44.5.1. `npm run package:desktop` собрал приложение, `npm run test:desktop:packaged` выполнил оба сценария (2/2), `node scripts/desktop/verify-mac.mjs` подтвердил целостность ad-hoc подписи. Это автоматизированный smoke локально собранного `.app`, а не ручная установка скачанного релиза на чистую машину, проверка стороннего AI-клиента человеком или подтверждение Windows/Linux/macOS x64. Выпуск требует всей матрицы и release gates из [release.md](release.md).
