# Проектные шрифты и текст

В разделе «Основы» библиотека «Шрифты проекта» импортирует локальные статические
TTF, OTF, WOFF и WOFF2. Один файл — одно точное начертание. Студия читает семейство,
вес и стиль из файла; название файла не определяет начертание. Повторный импорт
того же начертания не создаёт дубликат. Несколько файлов добавляются одним пакетом
операций с одной отменой. Если документ изменился во время импорта, пакет не
применяется поверх новой ревизии автоматически.

Файл хранится в `assets/<sha256>.<format>`, описание — в optional `Project.fonts`.
Код студии и проектные данные остаются разными папками. Копирование проекта вместе
с assets переносит шрифты на другую машину; CDN не нужен. Перед добавлением
проверьте, что лицензия разрешает использование и хранение файла в проекте.
Системная коллекция автоматически не подключается и не копируется.

## Текстовый слой

В инспекторе scene-слоя текста доступны точное начертание, существующий размер
текста, интерлиньяж и трекинг в CSS px, выравнивание и направление. Изменения
применяются кнопкой «Применить слой» через общий движок операций. Незавершённый
числовой ввод сохраняется; конфликтующая правка требует явного решения.

Без выбранного проектного начертания остаётся прежний системный шрифт студии.
Для выбранного файла синтетические bold/italic отключены. Студия не подбирает
другой локальный файл с похожим названием.

## Готовность превью и экспорт

Preview и снимок агента ждут `FontFace.load()` и layout перед маркером ревизии.
Ошибка файла или ограниченное ожидание возвращают диагностику
`PROJECT_FONT_UNAVAILABLE`; человек видит предупреждение у превью. Устаревшая
загрузка не добавляет начертание в другой проект. Смена descriptor инициирует
повторную проверку даже при наличии байтов в кэше.

React handoff использует те же стили текста и включает используемые файлы,
`fonts.css` и manifest с provenance `project`. Отсутствующий или несовместимый файл
даёт `MISSING_FONT`; такой результат не объявляется точным. Проект не меняется
при чтении, рендере или экспорте. Удаление неиспользуемого начертания убирает
описание; неизменяемые байты сохраняются для Undo и истории. Удалить используемое
начертание можно только вместе с явным переназначением ссылок в одном пакете.

## Контракт агента

Реестр начертаний агент читает через `project_read`; пагинация `document_read` не заменяет полный реестр.
После schema_read агент может использовать `addProjectFont`, `updateProjectFont`
и `removeProjectFont`, а текст выбирает `scene.textStyle.fontId`. Описание должно
соответствовать фактическим family/weight/style файла; подмена метаданных даёт
`FONT_METADATA_MISMATCH` при чтении ресурса. Допустимые поля и ограничения задают
`src/core/fonts.ts`, `src/core/text-style.ts` и service/schema.ts.

Импорт бинарного файла — UI-authorized POST `/api/fonts` с `{data,name}`
(base64 и название). Он возвращает проверенные метаданные и hash, но не меняет
ревизию документа. Добавление descriptor — отдельная revision-checked операция.
Существующий read-only asset transport обслуживает шрифты теми же ограниченными
путями, что и изображения; произвольные filesystem paths не принимаются.

## Текущие границы

До 128 начертаний в документе; до 8 MiB на файл, 32 MiB распакованных таблиц,
128 таблиц и 256 неизменяемых файлов шрифтов в папке assets. Backend проверяет
контейнер и метаданные, а Chromium OpenType Sanitizer проверяет файл при загрузке.
Коллекции, variable fonts и SVG-in-font пока отклоняются явно. Успешная загрузка
не означает полного покрытия всех символов: отсутствующие глифы браузер может
показать запасным шрифтом.

Это типографика целого слоя. Rich text, caret/IME, редактирование диапазона,
auto-size и добровольное подключение системных шрифтов остаются в #12.
Формат старых проектов не переписывается. Старый reader schemaVersion 2 без
поддержки optional fonts/textStyle может отвергнуть новый документ; используйте
версию студии, поддерживающую эти поля.
