# Формат проекта и восстановление

## Канонические данные

В schemaVersion 2 `project.json` объединяет manifest, страницы и токены. Обязательные поля: `schemaVersion`, `projectId`, `name`, `revision`, `library: {id,version}`, `theme`, `tokens`, `pages`. Страница содержит стабильный `screenId`, имя, `viewport.width` и `nodes`; узел — стабильный `id`, `type`, JSON `props`, именованные `slots` с вложенными узлами.

`assets/` содержит локальные ресурсы, `fixtures/` — дополнительные данные примеров. Ресурсы адресуются относительными путями `assets/...`, без абсолютных путей и traversal. Библиотека ресурсов принимает пассивное SVG-подмножество до 256 КБ и PNG. UI нормализует JPEG/WebP в PNG локально перед загрузкой. Растровый ресурс ограничен 8 МиБ, 8192 px по стороне и 16 млн пикселей; имена вычисляются из SHA-256 нормализованного содержимого. Каталог показывает использование; удаление используемого ресурса запрещено, архивирование сохраняет файл для истории. Эта загрузка assets не является редактируемым импортом SVG или проектов сторонних редакторов (#26/#33/#34). Документ не содержит функций, модулей, обработчиков событий или исполняемого HTML. Свойства ресурсов, включая вычисленные ссылки на токены, проверяются во всех режимах.

Каноническая сериализация сортирует ключи. Лимиты: 5 000 000 UTF-8 байт JSON, 10 000 узлов, 100 страниц, глубина 64; HTTP-пакет до 1 МБ. ID уникальны. Неизвестные типы и свойства сохраняются; неизвестная библиотека/версия отображается как недоступная. Несовместимая версия самой схемы отклоняется без перезаписи.

Токены имеют `{type,value,themes?}`. Типы: color, number, dimension, string, fontFamily. Alias и привязка: `{$token:"name"}`. Проверяются отсутствующие ссылки, циклы и типы. Экспорт JSON выдаёт отсортированный словарь вычисленных значений выбранной темы; CSS — `:root` с custom properties. Исходные ссылки и все режимы остаются в `project.json`. Это собственный формат, совместимость с DTCG не заявляется.

## Сцена, заливки и тени фрейма

Узел может содержать декларативный `scene`: вид примитива, локальные x/y/width/height,
rotation, opacity, fill/stroke, radius и clip. Геометрия, IDs и преобразования
описаны в [ADR сцены](adr/0001-portable-scene.md), машинный контракт —
[JSON Schema](adr/scene-v2.schema.json). Камера редактора не меняет эти координаты.

Для `scene.kind="frame"` необязательные `fills` и `shadows` хранят переносимые
заливки и тени. Заливка имеет стабильный внутри списка `id`, `kind`, optional
`enabled`, `opacity` и `blendMode`. Поддерживаются `solid` с `color`, `linear` с
`angle`/`stops` и `radial` с `center`/`radius`/`stops`. Цвет — структурированный sRGB
`{r,g,b,a}`: целые RGB 0…255 и alpha 0…1. Opacity заливки умножает alpha цвета;
opacity сцены действует отдельно на слой с потомками.

Первый элемент массива — верхняя заливка. Linear angle следует CSS: 0° вверх,
90° вправо. Перед CSS-сериализацией конечный угол приводится по модулю 360;
исходное число остаётся в документе. Это исключает browser clamp для огромных
конечных значений. Radial center задан долями ширины/высоты 0…1, положительные радиусы —
долями соответствующих размеров, до 4. Stops имеют offset 0…1 в неубывающем
порядке; одинаковые offsets создают резкую границу. До 16 заливок, 2…64 stops
на градиент. Blend modes — закрытый стандартный набор из `BLEND_MODES` в
`src/core/paint.ts`, смешивающий только фоны данного фрейма. Это не смешивание
всего слоя с произвольным внешним backdrop.

Тень имеет `id`, `kind: inner|outer`, `x`, `y`, `blur`, `spread`, `color` и optional
`enabled`. До 8 теней; смещения и spread ±4096 CSS px, blur 0…4096. Все числовые
значения конечны; неизвестные поля, повторные IDs, произвольный CSS/URL и неверные
цвета отклоняются до записи. Новые эффекты сохраняют inset stroke и начало
координат потомков.

Отсутствие `fills` сохраняет прежний `fill`. Явный пустой список или все выключенные
заливки дают прозрачный фон, не возвращая legacy fill. `shadows:[]` снимает новые
тени и сохраняет прежнюю обводку. Чтение не материализует новые поля и не меняет
старые документы. Более ранняя сборка без этого расширения может отклонить файл;
нельзя удалять поля ради открытия оригинала — используйте совместимую сборку.

Advanced paint на text/vector/component/image пока отвергается явно. Image fills,
несколько strokes и masks не считаются реализованными этим расширением #10.
Обычные `setNodeMetadata` используют ту же проверку, baseRevision, atomic save и
undo/redo, что и остальные изменения документа.

## Миграция и перенос

Пилотный schemaVersion 1 можно положить как `project.json` в отдельную папку и открыть через сервис. Миграция сохраняет ID и структуру, создаёт одну страницу и выбирает `builtin@1`. Встроенный renderer поддерживает Stack/Card content slots, Text, Button, Metric. Перед миграцией сохрани копию оригинала.

Миграции версии библиотеки задаются декларативно в SDK и запускаются явно через `applyLibraryMigration`; автоматической миграции и отдельного мастера UI пока нет.

Для переносимого snapshot останови запись и скопируй `project.json`, `assets/`, `fixtures/`, либо закоммить их в отдельный репозиторий. Новый checkout открывается через `STUDIO_PROJECT` с установленной совместимой библиотекой. Библиотека и её зависимости подключаются отдельно: документ не переносит исполняемый исходный код.

## Запись и история

Каждый пакет содержит `requestId`, `baseRevision` и типизированные операции. Пакет проверяется целиком; успешная транзакция увеличивает revision. Undo/redo также увеличивают revision. Сохраняемые квитанции делают повтор того же запроса идемпотентным; тот же ID с другим содержимым запрещён.

Владелец записывает временные файлы, выполняет fsync и атомарное переименование. `.studio/pending.json` позволяет закончить подтверждённую транзакцию после сбоя. `.studio/state.json` хранит историю/квитанции, `lock.json` исключает второго владельца. Умерший PID позволяет безопасное восстановление блокировки; живой владелец или непонятное состояние дают отказ вместо перезаписи. Сервис, MCP и UI используют одного владельца. Изменения UI получают через polling; SSE пока нет.

Предложения и аудит записываются отдельными атомарными файлами. При сбое между применением операции и обновлением предложения повтор использует квитанцию и завершает запись статуса без повторной правки. `.studio/connection.json` и `ui-connection.json` содержат разные ключи и имеют права 0600. Они не входят в экспорт или Git.

## Ошибки и восстановление

- `REVISION_CONFLICT`: перечитать документ и явно создать новый пакет; UI сохраняет конфликтующий черновик.
- `EXTERNAL_CHANGE`: канонический файл изменён в обход сервиса. Остановить владельца, сохранить обе версии, проверить файл и открыть проект заново. Для поддерживаемой синхронизации использовать API операций.
- `RECOVERY_REQUIRED`: запись завершилась частично. Прекратить правки, устранить причину файловой ошибки, перезапустить владельца; pending journal будет восстановлен.
- `LOCKED`: найти действующего владельца и подключиться к нему. Не удалять его блокировку вручную.
- Ошибка структуры/версии/symlink: исходник остаётся нетронутым; исправить отдельную копию.

Проверка внешнего файла перед записью защищает от уже обнаруженной правки, но не является filesystem CAS против некооперирующего процесса в момент rename. Не редактировать `project.json` напрямую при работающем владельце. История и квитанции пока не имеют автоматического ограничения размера; очистку выполнять только после сохранения переносимого snapshot и остановки сервиса. Если авария оставила guard восстановления блокировки, нужна ручная проверка процессов/копия данных — сервис безопасно отказывается от записи.
